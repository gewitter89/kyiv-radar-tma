# Київ Радар v1.37 — Telegram immersive header

## Зауваження користувача
На скриншоті видно службовий @username старого Telegram-бота в НАТИВНІЙ панелі Mini App. Вміст цієї панелі не належить HTML, тому приховування CSS з сайту або заміна тексту повідомлень не гарантує, що назва зникне.

## Правомірний спосіб зменшити панель
Офіційний Telegram WebApp API 8.0+ підтримує requestFullscreen(), exitFullscreen(), fullscreenChanged, fullscreenFailed, safeAreaInset та contentSafeAreaInset. Додаємо лише цей офіційний шлях.

- Для справжньої Telegram-сесії Android/iOS з методом requestFullscreen пробуємо fullscreen після tg.ready()/expand().
- Лише підтверджене isFullscreen=true додає CSS-клас, щоб не перекрити кнопки/статус-бар, якщо запит відхилено.
- Відступи беруться з --tg-content-safe-area-inset-* і нативного env(safe-area-inset-*); нативні елементи закриття не приховуються й не перекриваються.
- У «ⓘ Про дані» є доступне керування «Відкрити на весь екран» / «Повернути звичайний вигляд». Це також повторна спроба з жестом користувача, якщо авто-виклик не спрацював.
- Ручний вибір зберігається на пристрої. Після ручного виходу з fullscreen наступний старт не буде примусово відкривати повний екран.
- Старі Telegram, звичайний браузер і Desktop, де метод недоступний, працюють як раніше, без фальшивих CSS-підмін панелі.

## Що не можна пообіцяти
Full screen — це запит до Telegram, а не видалення @username. Різні версії Telegram можуть усе ще малювати власні контролери. Username бота @prostov_shrink_bot залишається робочим посиланням/ідентифікатором. Його не можна просто прибрати з Telegram-клієнта через CSS. Для окремої нової ідентичності бота потрібна погоджена міграція, оновлення webhook/бот-сервісів і перевірка контактів — це НЕ входить у цей PR.

## Якість
Playwright в ізольованій перевірці моделює Telegram API: авто-виклик, підтвердження події, безпечні відступи, ручний вихід і збереження вибору, web/desktop/старий клієнт, відхилений fullscreen. Жоден тест не вимагає реального токена/Telegram-акаунта.

## Релізні обмеження
Кумулятивна чернетка від #61. Потрібні all-green latest-head CI, перевірка iPhone Telegram WebView й Android, тест без відступів при unsupported native mode, резервне копіювання VPS і скоординований API/Pages реліз. Не міняємо бота, токен, GitHub main, продакшн або платні сервіси.

## Точна причина нижньої смужки Telegram
На наданому скриншоті показано **Mini App Bar** — системну панель, у яку Telegram згортає застосунок, коли користувач свайпає вниз по його заголовку. Її @username не входить до DOM нашої вебсторінки. requestFullscreen не прибирає смужку, якщо застосунок уже згорнуто; зміна CSS/кольору також не допомагає.

**Негайне рішення для користувача:** натиснути на цю смужку, повернутися до Mini App і **закрити** його через нативне меню Telegram, а не згортати. В оновленій версії також є кнопка `ⓘ Про дані → Закрити застосунок повністю`, яка з безпосереднього натискання викликає офіційний `Telegram.WebApp.close()`. На звичайному сайті без активної Telegram-сесії кнопка не відображається. Жодного автозакриття під час фонової роботи не вмикаємо: це могло би втрачати введені дані.

**Межа:** Telegram сам визначає, коли показувати Mini App Bar. З вебкоду не існує підтримуваного керування, яке повністю вимкне Mini App Bar для користувача на весь час; username зникне з неї лише коли поточний застосунок дійсно закрито. Для перейменування адреси бот-акаунта існують інші обмеження — новий бот не є рішенням для приховування системної смуги.
