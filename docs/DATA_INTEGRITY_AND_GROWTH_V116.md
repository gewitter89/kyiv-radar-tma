# Київ Радар 1.16 — якість джерел, дублікати та антишахрайство

## Продуктова обіцянка (якої поки не можна давати)
Орендар отримує **фактичні** квартири за своїм бюджетом і умовами, без повторів у стрічці, з чітким статусом перевірки, джерелом, історією ціни та зручним запитом контакту. Наявність, власник, 0% комісії та автономність підтверджуються **окремо** — жоден статус не випливає з тексту імпорту.

## Реальний стан на 17.11.2026
- `data/deals.json`: 150 записів (89 OLX, 61 DOM.RIA), 0 доказово підтверджених власників, контактів, актуальності й нульової комісії.
- Під кожним записом присутній URL і фото, але дати публікації в джерелі та `sourceLastSeenAt` немає.
- Дата `verifiedAt = "Імпортовано ..."` — дата імпорту, а **не** незалежна перевірка.
- Посилання і фото OLX/DIM.RIA не підтверджують дозволу на відтворення чи ліцензії. Перш ніж масштабувати джерела, потрібна правова/партнерська перевірка.
- Номер у публічному каталозі не зберігається; захищена видача контактів — окремий процес через Telegram.

## Надійний шлях надходження даних
1. **Власні оголошення:** подання добровільно через Telegram з дозволом на фото й контакт; окремий запис у модерації; тільки після дозволу на публікацію.
2. **Партнерські джерела:** письмова згода власника даних/провайдера, дозволені API-повноваження, визначені умови републікації, відгук згоди та видалення. OLX Partner API OAuth має обсяг авторизованого користувача; це не універсальний канал завантаження чужих квартир.
3. **Посилання з відкритих джерел:** лише за умов сумісного дозволу/ліцензії. Якщо права на фото та описи не встановлені — не копіювати їх у власний каталог; за потреби лишати посилання/допустимі метадані та перевіряти дозволеність такого використання.
4. Усе надходить до **непублічного ingest staging**, без прямої публікації в `/api/deals`.

## Вхідна схема для майбутнього ingest
- `canonical_property_id`, `source`, `external_listing_id`, `source_url`.
- `source_published_at` / `source_last_seen_at` (ISO-8601 UTC з підтверджених відповідей джерела).
- `source_license`, `photo_rights_status`, `submitted_by` (закриті).
- Нормалізовані `district`, `rooms`, `area_m2`, `price_uah`, `building_address` (рівень точності не вище дозволеного власником).
- `moderation_state`: pending → approved / needs_review / rejected / expired / withdrawn.
- `last_human_verified_at` і незалежні підтвердження: availability, ownership, contact, commission, generator, GPON. Жодне не підміняє інше.
- `media_fingerprints` лише для медіа, на які дозволено обробку, і без публікації сирих контрольних значень.

## Dedup policy
`scripts/catalog_integrity.py` — безпечний read-only звіт. Він фіксує:
- Ідентичні canonical URL або зовнішній source ID = висока черга **ручної перевірки**.
- Два чи більше однакові відомі медіаідентифікатори = висока черга **ручної перевірки**.
- Одне збігле фото = звичайна черга **ручної перевірки**.
- Схожий район/ціна/площа сам по собі **не доказ** дублю.
- Ні при яких сигналах система не встановлює `fraud = true` та не видаляє квартиру автоматично.
- Майбутня реальна дедуплікація: порівняння ліцензованих зображень за perceptual hash, адреса з будинком, планування, уповноважений зв’язок, історія зміни ціни, рішення модератора; із журналом і можливістю оскаржити.

## Anti-fraud + достовірність
- Підозріла передоплата, фальшива схема оплати, дублювання фото, невідповідність ціни/локації = **сигнали ризику**, не вирок користувачеві.
- Заборонити публічний статус «0% комісії» без окремого доказу; назву бота «Оренда 0%» змінювати лише окремо через BotFather.
- Окремі заявлені й перевірені умови генератора, ліфта, інтернету, води, тепла; у разі невідомості — «Не перевірено».
- Власник має підтвердити актуальність або оголошення переходить у чергу повторної перевірки. Не обіцяти точне вікно життя без `sourceLastSeenAt`.
- Модератор отримує скаргу з типом помилки; уповноважена особа перевіряє й може приховати, відновити, виправити з аудитом. Без автоматичних звинувачень.

## Повернення користувача: гейт перед Telegram-повідомленнями
- Тільки нові **дозволені**, схвалені та з датою першої публікації оголошення; історичний імпорт не означає «новинка».
- Підписка добровільна й окремо підтверджена; 1 дайджест на день за умовчанням, зупинка за одну дію, приватний Telegram ID не публікується.
- Ідемпотентність по `(user_id,search_id,canonical_property_id,event_kind)`; захист від повторних CRON і помилок Telegram.
- До реальної ліцензованої бази й consent + server-side збереження жодних автоматичних Telegram-оповіщень.

## Гейти запуску
1. Перевірити право використання джерел і фото, спростити видалення та скарги.
2. Підключити 3–5 **реальних власників за їхньої згоди**, провести справжнє тестування контакту в Telegram (не лише мок).
3. Протестувати відсутність дублювань, модерацію, погану мережу, ручні скарги, iOS/Android.
4. Перші 10–20 тестувальників: відстежувати тільки законні мінімізовані агрегати (перший підбір, корисні результати, вдалий запит контакту, скарги). Не продавати контакти, не удавати перевірки, не платити за штучні відгуки.
5. Тільки після цих кроків — маркетинг, запрошення агентств, масштабування джерел і необов’язкові оповіщення.

## Межі цього PR
Без змін VPS, BotFather, токена, production API та даних клієнтів. Звіт лише для команди/moderation, не публічний рейтинг шахрайства. Повний живий антифрод, легальна автоматична синхронізація даних та реальні push-сповіщення **ще не створені**.
