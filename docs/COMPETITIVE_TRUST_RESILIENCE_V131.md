# Київ Радар — конкурентний аудит, чесна обіцянка та anti-incident план (17.11.2026)

> **Статус:** продуктово-інженерна пропозиція, не доказ запуску функцій. Без реальних фідів/прав/перевірок не заявляємо про актуальність квартир, «безпечну угоду», перевірених власників або покриття всієї України. Жодних платних інтеграцій та змін VPS/бота/токена у цьому PR.

**Критичне обмеження OLX API:** офіційний FAQ, питання №6, прямо вказує: звичайний Partner API **не дозволяє читати чужі оголошення**; доступні власні оголошення авторизованого користувача. Це не законний канал для автоматичного імпорту всього OLX до нашого каталогу. User OAuth = лише згода конкретного власника на його записи; для стороннього агрегування потрібен **окремий підтверджений договір/ліцензований фід**, якщо OLX погодить такий спосіб. Не називати реєстрацію додатка або client credentials дозволом перепублікувати чужі дані.
Джерело: https://developer.olx.ua/ua/articles/faq (запитання 6) та https://developer.olx.ua/ua/articles/authorization-in-api .

**Реальний висновок:** ми не виграємо шляхом «ще одного великого списку». Цінність — пошук без зайвих кроків, зрозуміле джерело, чесний статус перевірки, зручне обране та відсутність фальшивих позначок. Поки партнерські дані не з'явилися — це гіпотеза позиціонування, не доведений результат.

## 2. Бренд та зрозумілий UX

- Основний бренд лишається **«Київ Радар»**. Зберегти погоджену стилістику Graphite / Kyiv Signal та наявний SVG-знак. Не міняти логотип тільки заради оновлення.
- Пропозиція короткого слогану для тесту: **«Житло — по суті.»** Нічого не обіцяє про юридичну перевірку чи відсутність комісії. Не публікувати без візуальної QA.
- Один головний маршрут: **Оренда / Купівля → місто → параметри → список/карта → джерело → запит контакту**. Кнопка «Обрані» має бути видимою без меню, але локальні записи не повинні приписуватися іншому лоту.
- На картці: тип угоди, ціна + валюта + період (місяць/доба/об'єкт), місто, тип об'єкта, джерело, «останній раз підтверджено» тільки з перевірюваним timestamp, окремі рівні надійності. Невідоме — «не зазначено».
- Відділити три екрани: **нічого не знайдено за фільтрами** / **зараз немає дозволених актуальних лотів** / **дані тимчасово недоступні**. Не відображати знятий лот через кеш.
- Mobile QA: 320px, 390px, 768px, десктоп, реальний iOS/Telegram WebView; клавіатура; 44px touch targets; prefers-reduced-motion; достатній контраст.
- Відновлювати пошук і фільтри при виході з «Обрані». Для синхронізації між пристроями лише verified Telegram initData і приватний server-side scope (issue #45), без публічних посилань на чутливі колекції.

## 3. Нульовий бюджет: пріоритет впровадження

**P0 — довіра, до розкручування:**
1. #7: історичний витік bot token лишається критичним **OPEN**; власник просив його не змінювати. Не повторювати значення в логах/PR. Важливо окремо узгодити ротацію до публічного запуску.
2. #14: не піднімати історичні 150 лотів до «актуальних»; review на права, походження, дату перевірки й complaints/takedown. Відсутність evidence → не публікувати як підтверджене.
3. #37: revocation/expiry мають прибирати дані з API, fallback, відкритих вкладок та push-повідомлень. Перевірити розбіжності після релізу.
4. **Коректний моніторинг:** HTTP/TLS/JSON/API status/витік приватних полів → failure. Дійсний порожній `deals: []` → **WARNING для оператора**, не «API down». Цей вузький fix реалізовано у `scripts/monitor_public_health.py` в цьому PR; він не сертифікує роботу сервера 24/7.

**P1 — зрозумілий продукт до пілоту:**
5. #50: завершити safe-identity для локального обраного, протестувати безпечну міграцію старого numeric-only сховища, вручну проглянути на телефоні. Не зливати неперевірений PR.
6. #40/#43: продаж/оренда, категорії, UAH/USD/EUR, орендна періодичність без мовчазної конвертації, URL/deeplinks, стани API error vs empty.
7. #34: перший юридично дозволений фід (а не scraping); контракт/дозволені поля/стан джерела; staging dry-run → review → ручне ввімкнення. Для 1 млн записів потрібні пагінація/індексація, не один JSON у браузері.
8. «Не цікаво» — локальне приховування з окремим відновленням; підписка на фільтр тільки після правдивих нових timestamp та explicit opt-in (#11).

**P2 — після підтвердження користі:**
9. Видимі зміни ціни лише за збереженим history + source evidence, з надійним ID. Тільки справжні помірні Telegram-сповіщення.
10. Кабінет реального власника, право змінювати/знімати власні лоти, модерація та аудит (#12).
11. Платне просування — лише після окремого дозволу, з маркуванням «Реклама», юридичною/платіжною перевіркою (#13).

## 4. Захист від збоїв — тестовані сценарії

| Інцидент | Правильна реакція | Перевірка |
|---|---|---|
| API недоступний / невалідний JSON | Чесний error і повторна спроба; не показувати старі «актуальні» | Fail у зовнішньому health, browser test |
| 0 дозволених лотів після revoke | Порожній каталог без хибної «помилки сервера»; попередження оператору | isolated zero-count test, smoke UI |
| Партнер відкликав права, feed прострочено | Fail closed в кожному read path, скидання кешів/алертів, журнал | revocation test, не тільки TTL |
| Потік 1 млн записів, batch partial failure | bounded streaming/pagination; транзакція або rollback; без публікації до review | stress/transaction test на синтетичних даних |
| Ціна/валюта/період не визначені | Не вгадувати та не конвертувати; тримати в staging | parser validation |
| Два оголошення про один об'єкт | Кандидат у дублі, а не автоматичний merge; ручний review | source-ID/permalink/photo hash tests |
| Фото/підозрілий feed/PII | MIME + actual decoding + limit, XXE/SSRF/HTML escaping, приватні поля без JSON leak | isolated upload/parser/API negative tests |
| Диск заповнений, SQLite WAL, VPS restart | backup на узгоджену копію, stop writers, restore rehearsal, health + Telegram smoke | disposable restore drill |
| Token з публічної історії | Критичний відкритий security issue до ротації; доступ/permissions мінімізувати | security review, без заяви «захищено» |

OWASP API guidance: https://owasp.org/www-project-api-security/ . Наступний production deploy тільки окремо із backup, health, real-device QA та rollback. Навіть успішний CI не замінює ці етапи.

## 5. Умови «готово» для першого реального користувача

- Щонайменше **один** справжній дозволений актуальний лот, який користувач може відкрити, відфільтрувати, зберегти й отримати контакт через перевірений Telegram flow. Кількість не маскує якість.
- **Жодного** підтвердженого статусу без evidence; жодного фіктивного відгуку, комісії чи цін.
- Пошук за 3–4 дії на вузькому телефоні; усі помилки пояснюються зрозуміло; 0 лотів не змішується з outage.
- 10–20 реальних тестувальників за добровільною згодою, вимірювати завершені запити контакту і скарги. Метрики не вигадувати.
- Готовність до масштабування оцінюється окремо від каталогу: реальний feed, дозволи, dedup review, пагінація, rollback, навантаження.

**Не зроблено цим PR:** UX overhaul, нативні пуші, 1 млн реальних об'єктів, verified feed, live VPS/API deployment, Telegram token rotation, оплата або зміна бренду.
