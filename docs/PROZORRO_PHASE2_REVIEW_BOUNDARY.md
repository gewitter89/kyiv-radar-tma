## Implemented staging chain
- `scripts/prozorro_candidate_handoff.py`: only the isolated pilot identity can read its cache; operator handoff emits sanitized candidate metadata on stdout. Transfer into a separate reviewer-controlled private directory; do not broaden pilot DB permissions.
- `scripts/prozorro_decision_ledger.py` and `scripts/prozorro_moderation_cli.py`: bounded append-only SQLite event log, explicit operator rights grant/revocation and per-item approval/revocation. New source grant invalidates all earlier approvals. Operator identity is the trusted OS account; no HTTP writer. No real rights or approvals issued by this code.
- `scripts/prozorro_staging_export.py`: accepts only the private sanitized handoff and ledger, seals the whitelisted result using a 32-byte private staging key. Stdout only; never redirect into the public repository. Root/operator must provision separate ownership and atomic private-file handoff; do not grant the collector write access to moderator decisions.
- `server/auction_snapshot.py`: validates HMAC, bounded file reads, strict fields and 60-second validity; clips individual expiry to the snapshot deadline. A snapshot signed just before withdrawal can remain visible until that deadline; this is bounded staging behavior, not instantaneous revocation. No automatic production export installed.
- `GET /api/auctions`: returns 404 unless APP_ENV is test/staging and KYIV_RADAR_AUCTIONS_PREVIEW=1, even if the browser flag is set. Returns 503 and zero rows on invalid/expired snapshot. No-store. For private staging only; use a protected same-origin staging proxy, not the existing public API. Set KYIV_RADAR_AUCTION_SNAPSHOT and KYIV_RADAR_AUCTION_KEY to absolute private files outside checkout. No private path/key/SQLite exposed in response.
- `auction-tab.js/css` and `index.html`: actual site includes disabled-by-default assets; isolated staging build sets window.KR_AUCTIONS_STAGING=true before loading script. No runtime toggle via URL, no auction request while flag is off. Modal supports deadline/price sorting, maximum starting price and local-only favorite IDs; expiry removes cards even from favorites, network errors hide rows, Telegram openLink when available. Not real-device verified yet.
- Tests: rights, projection, preview, full synthetic candidate->ledger->snapshot->API, browser viewports and mock Telegram. Exact-head CI required; real iOS/Android Telegram and same-origin staging deployment still separate acceptance tasks.
