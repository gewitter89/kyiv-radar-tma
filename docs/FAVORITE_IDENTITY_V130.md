# Київ Радар v1.30 — незмінна ідентичність «Обраних»

## Чому це потрібно

Раніше у браузері зберігалися **тільки** номери `kr_favs=[1,2,...]`.
Після перевантаження, зміни джерела, дедуплікації чи нового імпорту
номер картки може бути наданий іншому оголошенню. Відображати нову квартиру
як старе збереження — небезпечно й нечесно.

## Нова модель (локально, без акаунту)

`favorite-identity.js` утворює ключ із **джерела + HTTPS permalink**.
Не використовує поточний numeric `item.id`, назву, фото, ціну, власника,
телефон, координати чи позицію у каталозі.

- Нормалізація Unicode назви джерела, HTTPS-host, фрагмента і
  tracking query (utm/gclid/fbclid); public `id/offer_id/listing_id`
  зберігаються, щоб не змішати різні лоти.
- Розпізнавання однакових ключів на двох картках: **не можна зберегти
  неоднозначний об'єкт**, поки його не виправлять у джерелі.
- Збереження `kr_favs_v2 = {version: 2, keys: [...]}` у localStorage.
  Не зберігає картки, фотографії чи контактні дані.
- Якщо лот вилучили, збережений ключ залишається як недоступне посилання
  в приватному браузерному сховищі, але лот **ніколи не воскресає з кешу**.
- Пошук і фільтр «Обрані» працюють за новим ключем, а не numeric ID.

## Міграція старих збережень

**Не можна безпечно ідентифікувати старі `kr_favs` по номерах.**
Ні URL, ні джерело у старому форматі не зберігалися. Тому автоматично
прив'язати до нового каталогу старий ID — означає ризик показати зовсім
іншу квартиру.

Впроваджена безпечна карантинізація: старий список залишається
незміненим у `kr_favs`, не вважається підтвердженим «Обраним»;
у вкладці «Обрані» є пояснення і кількість старих записів.
Користувач повинен повторно знайти потрібні квартири та натиснути
сердечко. Старі номери можна видалити окремим підтвердженим натисканням.
Нова колекція не втрачається при цьому.

**Поведінка за відсутності permalink або джерела:** кнопка відключена;
ми не вгадуємо відповідність об'єкта.

## Перевірки

- новий числовий ID для тієї самої URL -> збереження залишається;
- той самий числовий ID з іншою URL -> жодного перенесеного сердечка;
- одна URL у двох картках -> не можна зберегти неоднозначні картки;
- старі номери не привласнюються жодним поточним оголошенням;
- зняття лота -> тільки повідомлення про недоступність, жодної
  копії фото/контактів з localStorage;
- приватний режим або пошкоджене сховище -> без падіння сайту;
- мобільний браузер, список, карусель, пошук, «Обрані», keyboard.

## Важливе обмеження

Це **локальне збереження**, не хмарна синхронізація.
Для синхронізації між пристроями потрібна окрема верифікована
авторизація, перевірка доступу до власних записів, аудит видалень,
захист від replay, згода і privacy review (issue #45).
В цьому PR не змінюємо Telegram токен, VPS, продакшн API чи платні джерела.

Публікація нових партнерських даних та ліцензування — окремі release gates.
